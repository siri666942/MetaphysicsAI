# 反向代理、域名、Docker 与代码 —— 宏观关系

用一张图和一个比喻把「用户输入域名 → 看到你的网站」整条链路说清楚。

---

## 一、一张图：请求怎么到你写的代码

```
用户浏览器
    │ 输入 https://beingecho.tech 或 http://beingecho.tech
    ▼
DNS（域名解析）
    │ 把 beingecho.tech 解析成你服务器的公网 IP，例如 1.2.3.4
    ▼
你的服务器（1.2.3.4）
    │ 请求到达 80 端口（或 443）
    ▼
Nginx（反向代理，跑在服务器上）
    │ 监听 80/443，按配置把请求「转交」给本机某个端口
    │ 这里配置成：把所有请求转到 127.0.0.1:5000
    ▼
Docker 容器（beingecho-app）
    │ 监听本机 5000 端口，里面跑的是你打好的「镜像」
    ▼
你的代码（Flask + 前端）
    │ 镜像里是 backend（Python/Flask）+ frontend（HTML/JS）
    │ 处理 / 和 /api/*，返回页面或接口结果
    ▼
响应原路返回 → 用户看到页面
```

- **域名**：让人记住的地址，DNS 负责把它变成 IP。
- **Nginx**：在服务器入口「接客」，按规则转给内部服务（这里是转给 5000）。
- **Docker**：把你的「应用+环境」打包成镜像，在容器里稳定跑在同一端口（5000）。
- **你的代码**：活在镜像里，真正处理请求、返回页面和接口的是它。

## 二、用生活比喻串起来

- **域名**：店名（beingecho.tech）。大家记店名，不记门牌号（IP）。
- **DNS**：查号台。别人报店名，查号台告诉你「这家店在 XX 街 XX 号」。
- **服务器**：整栋楼。门牌号就是公网 IP。
- **Nginx（反向代理）**：一楼前台。客人从正门（80/443）进来，前台不自己做业务，只负责把客人带到对应楼层/房间（转给 5000 端口的服务）。
- **Docker 容器**：楼里的一间「标准间」。房间里环境固定（Python、依赖、你的代码），只对楼内开放一扇门（本机 5000 端口）。
- **你的代码**：在标准间里真正干活的人。处理请求、算八字、返回页面，都是这段代码。

所以：**域名 → DNS → 服务器 → Nginx → Docker 容器 → 你的代码**，一环扣一环。

---

## 三、各层各干什么、谁管谁


| 层次             | 是什么                        | 谁配置 / 谁管                                                |
| -------------- | -------------------------- | ------------------------------------------------------- |
| 域名 + DNS       | 把「beingecho.tech」解析到服务器 IP | 你在域名服务商（阿里云/Cloudflare/等）配 A 记录                         |
| Nginx          | 监听 80（和 443），把请求转到本机 5000  | 你在服务器上配（本项目用 `setup-nginx.sh` + `nginx/beingecho.conf`） |
| Docker         | 用镜像起容器，容器里跑应用，对外只暴露 5000   | 你在服务器上跑 `deploy.sh`（构建镜像 + 起容器）                         |
| 代码（Flask + 前端） | 处理路由、接口、页面                 | 你改仓库里的 backend / frontend，再通过 `deploy.sh` 打新镜像、换新容器     |


- **改代码**：只动「你的代码」这一层；重新构建镜像、换掉容器后，Nginx 仍然把请求转到 5000，所以用户通过域名访问到的就是新版本。
- **改域名**：只动「域名 + DNS」和 Nginx 里的 `server_name`，不动 Docker 和代码。
- **改端口**：若应用改成监听别的端口，只需改 Nginx 里的 `proxy_pass` 和 `deploy.sh` 里的端口映射，域名和 DNS 可以不变。

## 四、和本项目脚本的对应关系

- **setup-nginx.sh**：只做「Nginx 这一层」—— 安装 Nginx、把 `nginx/beingecho.conf` 装到系统里并启用，让 80 端口的请求转到本机 5000。**首次在服务器上执行一次即可。**
- **deploy.sh**：只做「Docker + 代码」—— 停旧容器、用当前代码构建新镜像、起新容器（监听 5000）。**每次改完代码想发布，就执行这一条。** 若已配好 Nginx，脚本末尾会提示「用户通过域名即可看到本次更新」，并视情况重载 Nginx。

所以：**配置好 Nginx 之后，以后只要改代码 + 跑 `./deploy.sh`，用户用域名访问就能看到更新。**

---

## 五、小结

- **域名**：给人用的地址；**DNS** 把域名换成服务器 IP。
- **反向代理（Nginx）**：在服务器入口接请求，转给内部服务（本机 5000），这样用户用「域名」或「域名+80/443」就能访问，不用记端口。
- **Docker**：把你的运行环境和代码打成镜像，在容器里固定监听 5000，方便同一台机器上稳定、隔离地跑应用。
- **你的技术栈代码**：在容器里真正处理请求的 Flask 后端和前端静态资源。

整体就是：**域名 → DNS → 服务器 → Nginx（反向代理）→ Docker 容器（5000）→ 你的代码**；部署脚本只是把「Nginx 配置」和「Docker 构建与运行」做成两条清晰命令（首次 setup，日常 deploy）。
